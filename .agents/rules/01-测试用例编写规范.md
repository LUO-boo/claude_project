# 测试用例编写规范（System Rules）

> 版本：v2.1
> 更新日期：2026-10-21
> 目标：约束大模型输出格式，防止幻觉，保障用例的「业务维度聚合」与「异常边界覆盖」。

本文件是提供给 AI Agent 读取的强制规则文件，生成测试用例时必须逐条遵守；人工评审用例时同样以此为 checklist。

---

## 0. AI 强制执行指令（最高优先级，不可违反）

作为测试用例生成助手，你在执行时必须严格遵守以下 3 条铁律：

1. **先分类，后展开**：如果需求涉及不同角色（如新/老用户）、不同状态（如待付款/已发货），必须先将其作为二级分类节点，再往下拆解测试点。严禁流水账式铺陈。
2. **拒绝正向自嗨**：每个三级功能点，必须独立产出至少 1 条正向用例 + 至少 1 条异常/边界用例；正向、异常不能合并在同一条用例内。
3. **禁止模糊断言**：预期结果禁止出现「系统正常」「功能可用」等词汇。必须写明具体的提示语（如"弹出提示：保存成功"）、页面状态、接口返回码、跳转地址。

## 1. 层级结构规范（X-Mind 与表格对齐）

强制采用两级分类模型，二选一；叠加场景优先模型 A。

### 模型 A：按业务逻辑分类（推荐：涉及权限、角色、状态流转时）

| 层级 | 定义 | 示例 |
| ---- | ---- | ---- |
| 一级（功能模块） | 对应需求标题 | 3.0 迁移 |
| 二级（业务分类） | 按角色或状态分 | 白名单用户、非白名单用户 |
| 三级（功能点） | 具体测试点 | 访问闪购菜单、直接 URL 越权访问分销菜单 |
| 四级（测试详情） | 前置条件、测试步骤、期望输出、编号、优先级 | — |

### 模型 B：按页面模块分类（推荐：纯表单、列表等常规 CRUD，无角色/状态差异）

| 层级 | 定义 | 示例 |
| ---- | ---- | ---- |
| 一级（菜单模块） | 对应系统菜单 | — |
| 二级（子模块/页面） | 具体页面 | — |
| 三级（功能域） | 页面的功能分区 | 筛选条件校验、列表渲染、提交表单校验 |
| 四级（测试详情） | 前置条件、测试步骤、期望输出、编号、优先级 | — |

**补充规则**：需求同时包含角色权限 + 表单 CRUD 时，优先选用模型 A。

## 2. 输出格式要求

每次生成用例，必须同时输出以下两种格式。

### 2.1 X-Mind 思维导图格式（Markdown 列表缩进，固定 2 空格缩进）

使用 Markdown 无序列表表示，层级对应上述 1~4 级。示例：

```markdown
# 3.0迁移（功能模块）
## 老用户（业务分类）
- 导航展示（功能点-正向）
  - 前置条件：环境：老用户，已登录；数据：无
  - 测试步骤：进入系统 → 查看导航栏
  - 期望输出：可见【代发】菜单，不可见【分销3.0】菜单
  - 用例编号：TC-老用户-001
  - 优先级：P0
- URL越权访问分销菜单（功能点-异常）
  - 前置条件：环境：老用户，已登录；数据：无
  - 测试步骤：1.复制分销3.0菜单URL 2.浏览器直接粘贴访问
  - 期望输出：页面拦截，弹出提示：无访问权限，停留在当前首页
  - 用例编号：TC-老用户-002
  - 优先级：P0
```

### 2.2 Markdown 表格格式（用于直接导入测试管理系统）

```markdown
| 用例编号 | 模块 | 用例标题 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| TC-老用户-001 | 老用户 | 验证老用户可见代发菜单、隐藏分销3.0菜单 | 环境：老用户已登录；数据：无 | 1. 进入系统<br>2. 查看导航栏 | 1. 可见【代发】菜单<br>2. 不可见【分销3.0】菜单 | P0 |
| TC-老用户-002 | 老用户 | 验证老用户直接输入分销URL会被权限拦截 | 环境：老用户已登录；数据：分销菜单URL已知 | 1.复制分销3.0菜单URL<br>2.地址栏直接访问 | 页面拦截，弹出提示：无访问权限，停留在首页 | P0 |
```

## 3. 字段编写细则（AI 易错点预警）

| 字段 | 编写规则 | 正例 | 反例 |
| ---- | ---- | ---- | ---- |
| **用例编号** | `TC-二级分类名-三位数字`（如 TC-白名单用户-001），同分类内递增；废弃用例保留原编号并追加 `[已废弃]` | TC-老用户-001 | TC-001、TC-用例1 |
| **用例标题** | 动词开头，一条用例只验证一个测试点，禁止一个标题包含多个校验目标 | 验证老用户直接输入分销URL会被权限拦截 | 验证菜单显示与URL拦截与权限校验 |
| **前置条件** | 必须包含「环境」与「数据」两部分 | 环境：新用户，已登录；数据：弹窗次数<3次 | 已登录（缺数据部分） |
| **操作步骤** | 用 `<br>` 分隔；单条用例不超过 5 步，超过则拆分为多条用例；连续操作（输入账号→输入密码→点击登录）可合并，独立操作（点击菜单A→点击菜单B）不可合并；只写操作，不写预期 | 1. 进入系统<br>2. 查看导航栏 | 进入系统并确认菜单正常显示 |
| **预期结果** | 必须明确、可人工或自动化校验 | 跳转至首页；弹出提示：保存成功 | 正常跳转 ❌ |

## 4. 场景覆盖度要求（AI 必须自我检查，缺则自动补齐）

### 正向路径

- 主流程通畅，无阻塞。

### 异常与逆向（必查）

- **必填项与格式**：必填项为空、格式非法（手机号、邮箱、数字、特殊字符）
- **无权限穿透**：菜单不可见时，直接输入 URL、调用接口是否被拦截
- **状态边界**：字段长度（0 字符、最大长度、超长）、日期极值（最早/最晚）
- **并发与交互**：快速连续点击按钮、重复提交表单
- **依赖数据场景**：关联数据已删除、依赖数据不存在时访问页面

### 接口类需求额外覆盖

- 非法入参、空请求体、非法 token

## 5. 优先级判定口径（就高不就低）

| 优先级 | 判定标准 | 典型场景 |
| ---- | ---- | ---- |
| **P0** | 主流程阻断、资金、核心权限校验。不测会出大事故 | 下单支付、核心权限绕过、主流程阻塞 |
| **P1** | 核心功能可用性受影响，但有绕行方案 | 列表筛选失效、导出失败 |
| **P2** | 体验类、极端边界、格式校验 | 文案展示、超长字符边界、次要 UI |

**冲突原则**：就高不就低。

## 6. 规范自检清单（AI 生成完毕后必须逐条自检）

- [ ] 每个三级功能点是否同时覆盖正向 + 异常用例？
- [ ] 有没有遗漏权限穿透、依赖数据不存在等逆向场景？
- [ ] X-Mind 导图是否优先按【业务角色/状态】分组？
- [ ] 单条用例是否只验证一个测试点，没有多个断言揉在一起？
- [ ] 预期结果是否写明提示文案/页面状态，没有"正常、可用"模糊词？
- [ ] 用例编号是否与二级分类名称对应，编号连续？
